Voice notes to filed notes

I talk into my phone; a minute later the note is cleaned up and filed in the right place in my notes folder. Speech-to-text runs on my own GPU, an LLM decides where it goes, and plain code does all the writing.

SpeechWhisper large-v3-turbo on a 6 GB GPU
FilingLLM with no tools, JSON answer
CodePython stdlib, one web app module + one timer
StatusIn daily use since October 2026

The problem

Most of my ideas and to-dos show up when I'm away from the keyboard: driving, cooking, walking. Typing them on a phone is slow, and a plain voice memo app gives me a pile of recordings I never listen to again. I wanted to say "add to the garden plan: order bean seeds" and find that line in the garden plan, with the punctuation fixed and the "um"s gone.

Two rules came first: never lose a recording, even when the GPU box is off, and never let a voice note run anything. A transcript is data, not a command.

How it works

  1. Record. A small page in the phone's browser records with MediaRecorder and uploads the audio. The web app writes it to disk before doing anything else, so a crash or a dead GPU box can't lose it.
  2. Transcribe. The web app sends the audio to Whisper (large-v3-turbo through Speaches, which speaks the OpenAI transcription API) on the GPU box. Whisper gets a vocabulary prompt with the names I use a lot, so they come out spelled right. The raw transcript is saved as a note right away and is always kept.
  3. Clean and classify. A timer on the agent's container picks up raw transcripts every minute and asks an LLM, run with no tools, to fix punctuation, drop filler words, apply "scratch that", and pick an action: new, append (to a named note), claude (a request for my AI agent), diary, discuss or empty.
  4. Check and write. The answer goes back to the web app, which checks it and writes the file. It only ever creates notes or appends dated sections; it never edits or deletes. Then it sends a push to my phone with a link to the note.

The LLM proposes, the code decides

The model's answer is a proposal. The web app accepts only the six known actions, and an append target has to be a note that really exists. If the model names a note that isn't there, the text is saved as a new note that says where it was meant to go, instead of being dropped or written to a made-up path.

The prompt tells the model the transcript is data and not instructions. That helps, but it isn't the guardrail. The guardrails are that the model has no tools, its output is checked, and the worst a bad answer can do is put a note in the wrong folder, next to the untouched raw transcript.

Requests for my AI agent ("Claude, check why the backup was slow") are the part I was most careful with. They only become an unticked line in a queue file. When I next start a session, a hook shows the agent the list and it asks me which ones to do. Talking to my phone can't make the agent act on its own.

What broke: the GPU ran out of memory

On its first evening a dictation simply failed. The log showed Whisper answering 500 with a CUDA out-of-memory error. The GPU only has 6 GB, and a local LLM I run on the same card for other jobs was still holding most of it. The first version counted every error the server returned as a strike against the recording, and after three strikes it gave up on it. A busy GPU got the recording thrown out.

The fix was to sort failures by whose problem they are:

What happenedWhat it meansWhat the queue does
Server unreachableThe GPU box is off or awayStays queued, doesn't count as a try; the next timer run tries again
5xxThe server's own trouble: out of memory, model loadingStays queued, waits 1, 2, 5, 10, 20, then 30 minutes between tries; gives up and pushes a notification only after 2 days
4xxIt rejects this audioCounts as a try; gives up after 3
LLM down or out of quotaCleanup can't runRaw note stays, backs off from 5 minutes to an hour, one push so I know

One GPU means one transcription at a time, so a lock serialises them, and when the server says it's busy the rest of the queue waits too instead of hammering it.

except urllib.error.HTTPError as e:
    if e.code >= 500:                       # its trouble, not the recording's: queue it, back off

        rec["busy"] = n + 1
        rec["next_try"] = now + 60 * BACKOFF_MIN[min(n, len(BACKOFF_MIN) - 1)]

    rec["rejects"] = rec.get("rejects", 0) + 1   # 4xx: it refused this audio
except OSError:                                # unreachable: no count, try at the next run
    return False

Smaller things I learned

  • Spell out "scratch that" with an example. "Remove what came before it" is ambiguous when a correction follows, so the prompt carries one worked case: "Test the new model on Tuesday. Scratch that. Test it on Wednesday." becomes "Test the new model on Wednesday.", not "Test it on Wednesday." with nothing left for "it" to point at.
  • A vocabulary prompt is cheap and works. Whisper reads it as earlier text, so unusual names stop coming out as near misses.
  • Keep the raw transcript. Every filed note links back to it. When the model cleans too much, the original is one click away.
  • Make the queue visible. The raw note shows its status ("queued, waiting for the GPU box"), so I never wonder whether a recording got lost.
