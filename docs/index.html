Systems I built and run

I'm a systems engineer. At home I run a small lab: two Proxmox servers with about twenty containers, a GPU box for speech and local models, a NAS, monitoring and a web app that ties it together. These write-ups cover the four parts I'd most like to talk about.

Voice notes to filed notes

Phone dictation → Whisper on a GPU → an LLM tidies and files it. What happened when the GPU ran out of memory, and the retry queue that came out of it.

An LLM with guardrails

A daily briefing where code decides every fact and the model only writes the wording. No tools, separate calls for untrusted text, every answer checked.

Running an AI agent on real systems

Context files, skills as runbooks, hooks, memory, and a hard line: root steps go to a person. Including the time a "read-only" script deleted files.

One page for what needs a person

A collector, a list of action items with the exact fix, and acknowledge/snooze that knows when to bring something back. With a live demo.

How this was built

I build with an AI coding agent (Claude Code) running in its own container. I decide what gets built and how it should behave, review the changes, test them, and run the risky steps on the hosts myself. The agent writes most of the code. A lot of what I learned is about that split: what to hand over, what to keep, and how to make the agent's work checkable. That write-up covers it.

What's here and what isn't

The write-ups show the design, what broke and how I fixed it, plus short code samples in the repo. The samples are shortened and run on their own (each has a self-test). Names, addresses and anything personal are left out. Nothing here links into the lab: the demo and screenshots use made-up data.

A runnable tool from the same lab is on GitHub too: Eitri, a self-hosted save library and editor for single-player PC games, with a plugin per file format, a stdlib Python server and tests in CI.
